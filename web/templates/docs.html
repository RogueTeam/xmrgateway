Getting a token

  1. POST /api/v1/challenges returns a challenge id, its difficulty ({{.Difficulty}} bits) and the window to redeem it, which opens {{human .MinWait}} after it was issued and closes after {{human .Lifetime}}.
  2. Compute a hashcash stamp for the id. Redeeming early is refused however fast you are.
  3. POST /api/v1/tokens with the stamp returns a token valid for {{human .TokenValidity}}.
  4. Send it as X-API-Token to GET /api/v1/price, once {{every .RateLimit}}.

Every price response tells you when to ask next in next_request_at. A 429 carries Retry-After in seconds, at most {{human .RateLimit}}, and retry_at in UTC; a request without a token also gets 429, and an invalid or expired token gets 401.

Stamp format

Hashcash version 1, seven fields separated by colons:

1:BITS:TIME:CHALLENGE_ID:EXTENSION:RANDOM:COUNTER

BITS is at least the challenge difficulty and TIME uses the layout 2006-01-02T15/04/05Z0700. COUNTER is 8 bytes, big endian, standard base64. The stamp is valid when its SHA-224 digest starts with BITS zero bits.

The pow command makes one, using every core. PAYLOAD is the challenge id and DIFFICULTY its number of bits:

go run github.com/RogueTeam/xmrgateway/cmd/xmrgateway@latest pow PAYLOAD DIFFICULTY

Add -until with the challenge's not_before to have it wait until the stamp can be redeemed before printing it.
